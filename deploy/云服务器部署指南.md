## 先看这里：这个项目为什么不能"传个网页上去"

很多静态托管平台（Vercel、EdgeOne Pages 静态托管、GitHub Pages）的工作方式是：
**上传 HTML/CSS/JS → 平台返回文件**。它们的服务器只管发文件，不跑你的代码。

而这个聊天室是这样的：

| 需要什么 | 静态托管能不能满足 |
|---|---|
| `public/` 里的 HTML/CSS/JS | ✅ 可以 |
| **WebSocket 长连接**（消息实时推送） | ❌ 不行 —— 静态托管只处理一次性的 HTTP 请求 |
| **SQLite 数据库**（消息落库、昵称去重） | ❌ 不行 —— 没有服务端进程，就没有数据库 |
| **服务端生成房间口令**（防止陌生人进） | ❌ 不行 —— 口令逻辑在 server.js 里 |

所以本项目必须部署到**能跑 Node.js 进程**的地方，也就是云服务器。

好消息是：改造成本几乎为零。`server.js` 已经把所有关键东西做成了环境变量
（`PORT` / `HOST` / `DATA_DIR` / `ROOM_KEY`），加一个 systemd 服务就完事了。

## 选哪个地域？这一步决定你今天能不能上线

阿里云和腾讯云的**中国内地节点**有个硬性规定：
**用域名访问必须先完成 ICP 备案**（工信部要求，7-20 个工作日）。

但有个常见的误解要澄清：**备案的卡口主要在 80/443 端口 + 域名解析上。**
多个实测记录一致：用 `http://1.2.3.4:8000` 这种 **IP + 非标端口**访问内地服务器，
**实践中是能直接打开的**；被拦的是 80/443 端口和指向内地 IP 的域名解析。

> 风险提示：未备案的内地 IP 可能被 QoS 限速；平台扫描到疑似网站内容时
> 可能触发限流或要求备案。**两个人聊天的内测流量极小，风险很低。**

**你目前没有域名**，所以最稳的仍是海外/港澳台节点；但如果预算卡得紧，
内地节点 + IP + 非标端口也是可行方案。

### 路线 A：香港 / 新加坡 / 东京节点（最稳 —— 免备案零政策风险）

| 项目 | 说明 |
|---|---|
| 免备案 | ✅ 港澳台及海外节点不需要 ICP 备案 |
| 访问地址 | `http://<服务器IP>:8000/chat#key=<口令>` |
| 国内延迟 | 香港约 25-50ms；东京约 40-70ms；新加坡约 60-90ms |
| 缺点 | 比内地节点贵（轻量海外 1 年约 ¥672 vs ECS 内地 ¥99） |

**对聊天来说延迟完全无感** —— 你和朋友打字发消息，60ms 和 25ms 根本分不出来。

### 路线 B：内地节点 + IP + 非标端口（最便宜 —— ¥99/年）

内地节点便宜（**ECS 99 计划 ¥99/年，续费同价锁到 2029-03-31**），且：
- 用 IP + 8000 端口访问，实践中可用（见上面的澄清）
- 后续要绑定域名、长期运营，还是得走备案

**适合**：预算优先、愿意接受一点政策边界、两个人自用。

## 📱 手机党：不想开电脑就用 Workbench 网页终端

轻量应用服务器**自带网页版终端**（叫 Workbench），浏览器里直接操作服务器，

### ⭐ 最省事的方式：一条命令，不用传文件

部署脚本支持从网址直接下载代码包。服务器上一行命令搞定，
**你手机上完全不用传任何文件**：

```bash
# 把 <隧道地址> 换成你自己 launch.js 输出的那个 trycloudflare 域名
curl -fsSL https://<隧道地址>/deploy.sh -o /tmp/d.sh && bash /tmp/d.sh --self https://<隧道地址>/deploy.sh
```

> 这条命令会依次做完全部事情：
> 1. 下载 `deploy.sh`（部署脚本）
> 2. **自动推断**代码包地址并下载解包（`--self` 就是干这个的）
> 3. 装 Node.js 22 → 装依赖 → 建专用用户 → 注册 systemd 服务（开机自启+崩溃重启）
> 4. 自检并打印「公网访问地址」和「房间口令」
>
> **全程不用传文件、不用改任何参数、不用先上传任何东西。**
>
> 脚本里的 `--self` 会从脚本自身的地址推导出同目录的 `chat-room.tar.gz`。

> ⚠️ **前提**：你本机的 Cloudflare 隧道要开着（`node launch.js`）。
> 如果隧道断了，用下面的「方式 B」。

> 💡 **为什么手机上也行**：整条命令就是一段文本，Workbench 终端里粘贴一下就执行，
> 全程没有文件传输环节，4G 网络也不会卡。

### 方式 B：Workbench 文件管理上传（隧道断了就用这个）

## 第五步：放行端口（必做，否则外部打不开）

这是新手最常见的坑 —— **服务器上服务跑得好好的，但外面访问不了，
90% 是因为云控制台的防火墙没放行端口。**

### 阿里云 · 轻量应用服务器

控制台 → 轻量应用服务器 → 点进你的实例 → **防火墙** → **添加规则**

| 字段 | 填什么 |
|---|---|
| 协议 | TCP |
| 端口范围 | `8000` |
| 授权对象 | `0.0.0.0/0`（任何人可访问）|

### 阿里云 · ECS 云服务器（安全组不一样，最容易卡住）

控制台 → **ECS** → 实例与镜像 → 点进实例 → 点**安全组**链接
→ **配置规则** → **入方向** → 手动添加

| 字段 | 填什么 |
|---|---|
| 授权策略 | 允许 |
| 协议类型 | 自定义 TCP |
| 目的端口 | `8000/8000` |
| 源 | `0.0.0.0/0` |

> **ECS 和轻量的关键区别**：
> - 轻量的「防火墙」默认只开 22 和 80/443，**需要你手动加 8000**
> - ECS 的安全组**默认只放行 22**，其他端口全关 —— 必须手动加 8000 入方向
>
> 不管哪种，**加完规则要等 1-2 分钟才生效**，别加完立刻判定失败。

### 腾讯云

控制台 → 轻量应用服务器 → 实例 → **防火墙** → 添加规则，同样配置。

> 更安全的做法：把授权对象改成你朋友家的公网 IP，
> 这样只有他能连。但家里的 IP 会变，路由器重拨就失效了。
> 内测阶段建议先用 `0.0.0.0/0` —— **房间口令本身就是门禁**。

## 🔄 一个月到期了怎么迁移

轻量 1 个月的套餐到期后：自动停机 → **数据保留 15 天** → 超 15 天永久删除。
迁移只需要一个文件（数据库 + 口令），几分钟搞定。

### 第 1 步：到期前 15 天内，导出备份

```bash
cd /opt/chat-room && bash deploy/backup.sh
```

### 第 2 步：把备份文件下载到本地

在服务器上执行，拿到文件下载地址：

```bash
ls -lh /opt/chat-room/backups/
```

然后用浏览器访问 `http://<你的IP>:8000` 旁边的「文件管理」（Workbench 左侧）
把 `chat-data-*.tar.gz` 下载到手机/电脑。

```bash
# 新服务器上
mkdir -p /opt/chat-room && tar -xzf ~/chat-room.tar.gz -C /opt/chat-room

systemctl start chat-room
```

## 常见问题

### Q: 页面打不开，显示「连接超时」

按顺序排查：
1. **云控制台端口放行了吗？** ← 最常见
   - 轻量 → 防火墙 → 加 TCP 8000
   - **ECS → 安全组 → 入方向 → 加 TCP 8000**（ECS 默认只放行 22，最容易漏）
2. 服务器上 `systemctl status chat-room` 是 active 吗？
3. 服务器本机 `curl -s http://127.0.0.1:8000/chat` 有输出吗？
   - 有输出 → **服务是好的**，问题 100% 在云防火墙/安全组
   - 没输出 → 服务本身有问题，看 `journalctl -u chat-room -n 50`
4. 用的 IP 对吗？（控制台实例卡片上的公网 IP，注意不是内网 IP）

> 排查小技巧：部署脚本已经自动检查了端口是否在 LISTEN。
> 输出里看到「端口监听：8000 已在 LISTEN ✓」说明服务端完全正常，
> 只剩云防火墙/安全组这一件事没做。

### Q: ECS 买了之后登不上去，提示密码错误

ECS 的 Linux 镜像**创建时不会设 root 密码**（用的是密钥对登录）。
去控制台：ECS → 实例列表 → 找到实例 → 右侧「更多」→「重置密码」，
设一个密码，等 1-2 分钟生效，再用 `ssh root@你的IP` 登录。

> 也可以改用密钥登录：创建实例时选「密钥对」，
> 然后本地用 `ssh -i 你的密钥.pem root@你的IP`。
> 但对第一次用云服务器的人，密码登录更省事。

### Q: 3M 带宽够用吗（ECS 99 元那档）

够。本项目首屏资源总共约 32KB，3M = 375KB/s，
**加载只要 0.09 秒**。而且 WebSocket 空闲时不传数据，
两个人聊天的流量小到可以忽略。

### Q: 页面打开了，但消息发不出去

看浏览器 F12 → Network → WS，状态必须是 `101 Switching Protocols`。

- 不是 101 → WebSocket 被中间层断了。先确认没用代理/VPN。
- 连不上 → 检查端口放行是否真的生效（有时 IPv6 规则优先）。

### Q: 朋友进来说「房间口令不正确」

他用的链接没带 `#key=`。把完整的带口令链接重新发给他。

### Q: 房间口令能改吗

能。改 `/opt/chat-room/data/room.key` 里的内容，然后：

```bash
systemctl restart chat-room
```

改完记得把**新链接**重新发给朋友。

### Q: 消息存多久

默认 7 天后自动过期删除（`RETENTION_MS` 控制）。

### Q: 服务器会不会被陌生人进

不会。房间口令是门禁：
- 没口令的连接**当场被拒**，不创建用户行、不占昵称、不进成员列表
- 口令 12 位随机 hex（48 位熵），暴力猜不现实

### Q: 以后想买域名 + 上 HTTPS

见 `deploy/生产部署.md`，里面是 Nginx + certbot 的完整流程。
前提是域名已完成 ICP 备案。

## 附：为什么部署脚本用 `npm ci --omit=dev`

`package.json` 里 `@camera.ui/cloudflared`（本地隧道工具）被放在 **devDependencies**：
- 服务器上**用不到**它 —— 那是 `launch.js`（本机 + Cloudflare 隧道）用的
- 放 dev 后，`npm ci --omit=dev` 只装 `ws` 一个包，秒级完成，不用下几十 MB 的二进制

`server.js` 只依赖 `ws`（WebSocket 库），其余全是 Node.js 内置模块
（`node:http` / `node:sqlite` / `node:crypto` / `node:fs`）。
