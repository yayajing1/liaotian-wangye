# 自定义域名绑定指南

> 目标：把 `https://chat.你的域名.com/chat` 变成永久地址，替代每次重启都会变的隧道地址。

---

## 零、朋友说「打开有危险警告」—— 根因在这

这是最常见的问题，先说清楚**为什么**，不然会白折腾：

| 现象 | 原因 |
|---|---|
| 微信/手机打开链接，弹「**你的连接不是私密连接**」「安全警告」，要手动点「继续访问」 | 现在用的是 **Let's Encrypt 的 IP 证书** |
| 电脑 Chrome 上没事，手机上却报警 | IP 证书在 **iOS Safari / 微信 X5 内核 / 老安卓 Chrome** 上不被信任 |

**IP 证书 vs 域名证书：**

| | IP 证书（现在） | 域名证书（要换成的） |
|---|---|---|
| 有效期 | **7 天**（Let's Encrypt 的 IP 证书本来就短） | **90 天** |
| 手机上是否报警 | ⚠️ **会**（很多手机不认 IP 证书） | ✅ 不会 |
| 浏览器支持 | 只有部分新版本认 | 全球都认（标准 DV） |
| 换 IP 要重签 | ✅ 要 | ❌ 不用 |

**结论：绑定域名是根治「危险警告」的唯一办法。** 不是配置问题，是证书类型的问题。

## 一、先理清三件事

### 1. 你的服务器在境外，不需要 ICP 备案

阿里云官方口径：**备案看的是服务器在不在中国内地。**

| 服务器位置 | 需要 ICP 备案？ |
|---|---|
| 中国内地（杭州、上海、北京…） | ✅ 需要 |
| **中国香港 / 中国澳门 / 中国台湾** | ❌ 不需要 |
| **新加坡、东京、硅谷、伦敦…** | ❌ **不需要** |

你的服务器在**新加坡（亚太东南1）** → **不需要备案**。

> **常见误解：「阿里云是国内厂商，服务器是从阿里云买的，所以应该能备案呀？」**
>
> **不成立。** 判定依据是**服务器机房的物理落地位置**，跟厂商国籍无关 —— 这叫
> 「**服务器所在地原则**」。《非经营性互联网信息服务备案管理办法》约束的是
> 「在中国境内提供服务」，锚点是机房在不在境内。
>
> 而且阿里云**自己也不受理**境外节点的备案申请，官方文档原文：
> 「使用阿里云中国内地服务器，只有这样，阿里云才能为您备案。
> **不符合条件的情况：用阿里云香港、海外服务器？—— 无需备案。**」
>
> 换句话说：**不是「不能备案」，是「不需要备案」**。真要备案，得换一台
> 中国内地节点的机器 —— 而那样阿里云的监测系统会强制要求先备案才能访问。
>
> 实测归属（`ipinfo.io/8.222.185.143`）：
> `country: SG` / `city: Singapore` / `org: AS45102 Alibaba (US) Technology Co., Ltd.`
> —— 厂商是阿里云没错，**机房在新加坡**。

> **补充说明**：阿里云明确说过「通过域名使用非标准端口访问内地服务器，该域名仍须备案，**端口不改变备案义务**」。
> 所以「换个端口绕备案」这条路不通 —— 但你在境外，本来就不需要备案。
>
> **另外**：境外服务器 + 域名，**在国内访问不会被拦截**（这和境内未备案网站被封是两回事）。
> 唯一的"代价"是国内访问境外服务器的延迟略高一点，比 200ms 上下，日常聊天完全无感。

### 2. 域名 vs IP 证书：区别很大

**结论**：有域名就用域名证书 —— 少 30 倍续期次数，还消掉手机上的危险警告。

### 3. 数据存在哪？

**数据存在服务器上，不在任何一台设备上。**

```
                    ┌─────────────────────┐
  你的手机 ────────┤                     │
  朋友的手机 ──────┤   云服务器（新加坡）  │  ← SQLite 数据库
  你的电脑 ────────┤   /opt/chat-room/data│     存所有消息 + 昵称占用
                    └─────────────────────┘
```

- 消息、历史昵称、房间口令 → 存在服务器的 `data/chat.db` 和 `data/room.key`
- **任何设备打开同一个地址，看到的都是同一份数据**
- 浏览器本地只存一个「我是谁」的匿名 ID（`localStorage`），删了也无所谓，重新分配一个即可
- 换设备、重装浏览器、清缓存 → **消息一条不少**

> 本机跑隧道时，数据在你电脑的 `data/` 目录。
> 部署到云服务器后，数据在服务器上 —— 这才是「任何设备打开数据都在」的真正含义。

## 三、解析 DNS

### 步骤

1. 阿里云控制台 → 左侧 **云解析 DNS** → 找到你的域名 → 点 **解析设置**
2. 点 **添加记录**，填：

| 字段 | 填什么 |
|---|---|
| 记录类型 | **A** |
| 主机记录 | `chat`（或你想要的子域名） |
| 解析线路 | 默认 |
| 记录值 | **你的服务器公网 IP** |
| TTL | **10 分钟**（默认值就行） |

3. 保存。等 **10 分钟**左右生效（最长 24 小时）。

### 验证解析生效

在你自己电脑上跑：

```bash
# Windows
nslookup chat.你的域名.com

# macOS / Linux
dig +short chat.你的域名.com
```

返回的 IP 应该等于你的服务器公网 IP。

## 四、在服务器上签发域名证书

DNS 生效后，在服务器 Workbench 里执行：

```bash
cd /opt/chat-room/app
bash deploy/bind-domain.sh --domain chat.你的域名.com
```

### 一键脚本做了什么

1. 校验域名格式
2. 查 DNS 解析，**对比是否指向本机 IP**（不一致会提示你改 A 记录）
3. 检查 80 端口通不通（ACME 验证要用）
4. 用标准 Let's Encrypt 签发**域名证书**（90 天有效）
5. Nginx 的 `server_name` 同时接受域名和 IP 直连（IP 留着当备用）
6. 加上 **HSTS**（浏览器强制 HTTPS，不会再弹「不安全」）+ 隐藏 nginx 版本号
7. 装好自动续期钩子（续完自动重载 nginx）
8. 验证证书和网站

> 老的 `deploy/https-setup.sh --domain xxx` 也能用，效果一样。
> `bind-domain.sh` 是专门为「从 IP 切到域名」这个场景写的，步骤更细、提示更清楚。

### 或者部署时一步到位

```bash
cd /opt/chat-room/app
bash deploy/deploy.sh --git https://github.com/yayajing1/liaotian-wangye.git --https --domain chat.你的域名.com
```

## 五、验证

```bash
# 1. 证书签给域名了吗
echo | openssl s_client -connect chat.你的域名.com:443 2>/dev/null \
  | openssl x509 -noout -text | grep -A1 "Subject Alternative Name"
# 期望看到：DNS:chat.你的域名.com

# 2. HTTPS 通不通
curl -s -o /dev/null -w "%{http_code}\n" https://chat.你的域名.com/chat
# 期望 200

# 3. 一键体检（服务器上跑）
bash deploy/verify.sh --domain chat.你的域名.com
```

最后一条会输出全绿报告，顺带检查 8000 是否真的关闭了。

## 七、常见问题

### Q: 签证书报 `Timeout during connect`

**八成是 80 端口没放行**。ACME 的 http-01 验证必须能通过 80 端口访问到服务器。

检查：阿里云控制台 → 轻量应用服务器 → 实例 → **防火墙** → 确认有 TCP 80 规则。

### Q: 报 `too many certificates already issued`

同一组域名在 7 天内有签发次数上限。等几小时重试，或用测试环境验证配置对不对：

```bash
~/.acme.sh/acme.sh --issue --server letsencrypt_test -d chat.你的域名.com -w /var/www/letsencrypt
```

测试环境通过 → 说明配置没问题，是正式环境的频率限制。

### Q: 报 `Invalid response from http://chat.你的域名.com/.well-known/acme-challenge/`

两种可能：

1. **DNS 没生效** —— 域名还指向旧 IP 或没解析。用 `dig` 确认。
2. **80 端口被 Nginx 的跳转拦了** —— 检查 `/etc/nginx/sites-available/chat-room` 里 `location ^~ /.well-known/acme-challenge/` 那段还在不在。

### Q: 浏览器显示「证书域名不匹配」

说明签的是 IP 证书，不是域名证书。重跑：

```bash
bash deploy/bind-domain.sh --domain chat.你的域名.com
```

### Q: 绑好域名了，手机上还是弹「危险警告」

按顺序排查：

1. **朋友手机上还开着旧的 IP 链接** —— 让他用新链接（域名那个）重新打开
2. **微信缓存了旧页面** —— 让朋友在微信里「清一下缓存」，或用「在浏览器打开」
3. **系统时间不对** —— 手机时间偏差超过几天，证书会被判为无效。让朋友自动对时
4. **证书真的签成功了吗** —— 服务器上跑：

```bash
echo | openssl s_client -connect chat.你的域名.com:443 -servername chat.你的域名.com 2>/dev/null \
  | openssl x509 -noout -subject -dates -ext subjectAltName
```

期望看到 `DNS:chat.你的域名.com`（不是 `IP Address:...`）。

### Q: 开了 HSTS 之后网站打不开了

HSTS 会让浏览器**强制走 HTTPS**，如果证书之后出问题了，浏览器会直接拒绝访问，
连「继续访问」都不给。

解开的方法：

- **Chrome / Edge**：`chrome://net-internals/#hsts` → 底部「Delete domain security policies」→ 填域名 → Delete
- **Firefox**：`about:net-internals/#hsts` → 找到该域名 → Delete
- **手机**：清除浏览器数据

> 所以绑完域名后，先确认证书和自动续期都正常，再让朋友用新链接。

### Q: 换了个域名，旧域名还有效吗？

旧证书还在，但旧域名的 DNS 不再指向这台服务器就访问不了。重签即可。

### Q: 服务器 1 个月后到期了，域名怎么办？

- 域名是独立资产，**不会因为服务器到期而失效**，续费服务器后继续用
- 但如果长期不续服务器，域名解析指向空 IP，链接就打不开
- 建议：域名**开自动续费**（一年几十块），服务器到期前用 `deploy/backup.sh` 把数据导出来

## 八、方案对比：隧道 vs 服务器 vs 域名

| | 隧道（trycloudflare） | 服务器 IP | 服务器 + 域名 |
|---|---|---|---|
| 成本 | 0 | ¥0（已买） | ¥0 + 域名 6～76 元/年 |
| 地址稳定性 | ❌ 每次重启都变 | ✅ 永久 | ✅ 永久 |
| 需要电脑开着 | ✅ 是 | ❌ 否 | ❌ 否 |
| 证书有效期 | Cloudflare 自动 | 7 天 | **90 天** |
| 手机弹「危险警告」 | ❌ 会 | ⚠️ **会** | ✅ **不会** |
| 换 IP 麻烦吗 | 不适用 | 要重签 | 不影响 |
| 需要 ICP 备案 | 不需要 | 不需要（境外） | 不需要（境外） |
| 适合 | 临时演示 | 内测够用 | **长期使用** |

**建议路径**：现在先用隧道（已经给你跑起来了）→ 服务器部署完用 IP → 买域名后绑上 → 域名就是最终地址。

## 九、附带：Cloudflare 托管域名的另一种玩法

如果你在 Cloudflare 而不是阿里云买域名，还能用 **命名隧道**（Named Tunnel）：

- 好处：服务器**完全不需要开放 80/443 端口**，由 Cloudflare 中转，还能加 Zero Trust 访问控制
- 代价：配置步骤多（改 NS 委派要等几小时），而且要装 cloudflared 常驻服务
- 适合：以后想把服务藏起来、不暴露服务器 IP 时

内测阶段没必要，等真的要长期跑再考虑。
