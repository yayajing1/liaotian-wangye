# 买完服务器之后：照着做，一步不缺

> 适用：阿里云**轻量应用服务器**（新加坡，2核2G，1个月，¥0）
> 目标：拿到一个**朋友用 IP 就能直接访问**的聊天室，带 HTTPS 小锁

---

## 总览：你只需要做 3 件事

| # | 谁做 | 动作 | 耗时 |
|---|---|---|---|
| 1 | **你** | 控制台放行端口（80 / 443） | 2 分钟 |
| 2 | **你** | Workbench 里粘 1 行授权命令 | 1 分钟 |
| 3 | **我** | SSH 进去把部署全做完 | 5 分钟 |

做完你手里会有两个东西：
- `https://<服务器IP>/chat#key=xxxxxxxxxxxx` → **发给朋友，直接聊天**
- `https://github.com/yayajing1/liaotian-wangye` → **源码仓库**

---

## 第 1 步：放行端口（⚠️ 必须先做）

**路径**：阿里云控制台 → 轻量应用服务器 → 点你的实例卡片 → 左侧「**防火墙**」→ 右上「**添加规则**」

> ⚠️ 轻量服务器只有「**防火墙**」，没有「安全组」。看到「安全组」说明进错产品了，退回重来。

添加**两条**规则：

| 协议类型 | 端口范围 | 授权对象 | 用途 |
|---|---|---|---|
| TCP | `80` | `0.0.0.0/0` | ACME 签证书验证（**不给这个签不出证书**） |
| TCP | `443` | `0.0.0.0/0` | HTTPS 入口，小锁就靠它 |

点「确定」。再点一次「添加规则」加第二条。

**加完应该有 3 条**（22 是默认的，别删）：

| 端口 | 协议 | 授权对象 |
|---|---|---|
| 22 | TCP | 0.0.0.0/0 | 默认，SSH 用，别删 |
| 80 | TCP | 0.0.0.0/0 | 你刚加的 |
| 443 | TCP | 0.0.0.0/0 | 你刚加的 |

> 💡 **8000 要不要加？**
> 加 HTTPS 后 Node 只监听 `127.0.0.1`，8000 不需要暴露公网。
> 但**建议先加一条 8000**，好处是：部署完到 HTTPS 装好之间有个时间差，
> 那种阶段先用 `http://IP:8000/chat` 确认服务真的活了，
> 比等 HTTPS 全套跑完再排查省事得多。装完 HTTPS 后再删掉这条。
>
> 放行后**等 1-2 分钟**才生效，别加完立刻判定失败。

---

## 第 2 步：打开 Workbench，粘一行命令

**路径**：阿里云控制台 → 轻量应用服务器 → 点你的实例 → 右上「**远程连接**」→ 选「**Workbench**」

### 2.1 首次登录要设密码

如果提示登录失败/要求密码：
**回到实例列表 → 「更多」→ 「重置密码」** → 设一个 → 重置完要**重启实例**才生效。

> 轻量服务器购买时如果设过密码就不用这步。
> 提示「确认指纹」时，把它给的那串长字符复制粘贴进去即可。

### 2.2 粘这一行

登录进去后（看到 `root@...#` 提示符），粘贴这行并回车：

```bash
curl -fsSL https://raw.githubusercontent.com/yayajing1/liaotian-wangye/main/deploy/grant-ssh.sh | bash
```

### 2.3 它会打印什么

```
===== 1/4 writing SSH public key =====
  key written ok
===== 2/4 adjusting sshd config =====
  sshd_config updated & validated ok
===== 3/4 reloading sshd =====
  sshd reloaded ok
===== 4/4 server info =====
  PUBLIC_IP: 8.212.xxx.xxx
  OS: Ubuntu 22.04.5 LTS
  ARCH: x86_64
  USER: root
  NODE: not installed
  GIT: not installed
  CPU: 2 cores
  MEM: 2048MB total
```

### 2.4 你要做的

把 **`PUBLIC_IP:` 后面的那串数字**发给助手。

就这样，**服务器上的活全部由助手完成**（拉代码、装 Node、建 systemd、配 HTTPS、体检验证）。

```
  ✓ 证书剩余有效期 > 3 天 ✓
[4] 本机功能自测
  ✓ HTTPS 首页返回 200 ✓
  ✓ HTTP 正确跳转到 HTTPS（301）✓

[5] 证书自动续期
  ✓ cron 续期任务已注册 ✓
  ✓ systemd timer 兜底已启用 ✓
[6] 公网侧测试
  ✓ 公网 HTTPS 通（200）✓
  ✓ 8000 公网已关闭（连不上）✓ —— 这正是想要的结果
```

## 第 4 步：收尾 —— 删掉 8000 规则

回到**控制台 → 轻量应用服务器 → 实例 → 防火墙**，
找到 8000 那条规则 → 点右边「**删除**」→ 确认。

删完再测一次：

```bash
# 在你自己电脑上跑
curl -s -o /dev/null -w "HTTPS: %{http_code}\n" https://<服务器IP>/chat      # 期望 200
curl -s -o /dev/null -w "HTTP8000: %{http_code}\n" http://<服务器IP>:8000/chat # 期望 000
```

**8000 返回 `000`（连不上）才是对的** —— 返回 200 说明防火墙规则还没删。

## 第 5 步：发给朋友

```
https://<服务器IP>/chat#key=xxxxxxxxxxxx
```

- 浏览器打开就有**小锁** ✓
- 聊天走 `wss://`（加密）✓
- **不用注册登录**，进房自动分昵称和头像色
- 带 `#key=` 的链接直接进；**没口令的进不来**（内测门禁）

> ⚠️ **口令是唯一的钥匙**，别发到群里。私聊发给朋友即可。

## 常见问题

**Q：签证书报 `Timeout during connect`？**
八成是 80 端口没放行或还没生效。等 1-2 分钟后重跑：
```bash
cd /opt/chat-room/app && bash deploy/https-setup.sh
```
脚本可重复执行，不会破坏已有部署。

**Q：证书能撑多久？**
IP 证书有效期 **160 小时（6.6 天）**，靠 cron + systemd timer 双保险自动续期。
> 想要 90 天有效期就得有域名（域名证书）。买域名时**别勾「域名备案」**——你在境外，勾了反而要去填备案资料。

**Q：朋友说打不开？**
按顺序查：① 防火墙 80/443 放行了没 ② 是不是让他访问了 `localhost` ③ 让他把浏览器报错截图发你。

**Q：服务器还有多久到期？**
你买的是 **1 个月**，有效期到 **2026-12-26**。
到期前要迁移，备份用：
```bash
cd /opt/chat-room/app && bash deploy/backup.sh
```
备份脚本用 SQLite `.backup` 做一致性快照，迁移到新机器后直接解开就行。

**Q：数据存在哪？**
服务器上 `data/chat.db`（SQLite）。**不在任何一台设备上**——
所以「任何设备打开，历史消息都在」。本地浏览器只存一个匿名设备 ID。

## 应急：如果 Workbench 用不了

在你自己电脑上用 SSH（Windows 有内置 OpenSSH）：

```bash
ssh root@<服务器IP>
```

密码是控制台「重置密码」设的那个。
连上后照样执行第 2.2 步那一行命令即可。
